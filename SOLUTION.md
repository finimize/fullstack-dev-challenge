# Solution notes

## Approach

Explored repo and read README.md thoroughly to understand current codebase structure. Worked backwards from the
acceptance criteria to identify any edge cases that would need highlighting in Claude prompt. For example, important to
note that there needed to be a single shared contract between the server and the client for API request/response shapes.

On the server side, responsibilities are clearly split so the code reads the way a larger service would:

- `routes/projections.ts` — HTTP concerns only: parse query and call relevant service
- `middleware` — directory would be necessary once authentication and other middleware is added
- `app.ts` - exposes a `createApp()` factory so tests can spin up the app
  in-process with supertest

On the client side I used the following hooks to ensure a smooth user experience:

- `useDebouncedValue` to throttle slider values
- `useProjection` fetches on change, and uses an `AbortController` to cancel in-flight requests so as to avoid race
  conditions caused by fast changing input and/or slow fetches

## What I like

- The request handling to stop repeated requests spamming the server and producing bad a UX.
- A simple shared contract
- O(1) implementation of the closed-form future-value formula rather than a recursive implementation

## What I'd improve or do next

- `PROJECTION_YEARS = 50` currently lives on both the server and the client. It should have one source of truth. I would
  want the next feature to be an input which allows users to scale the projection years.
- The server returns a 400 if the inputs are invalid, but the client doesn't handle it and
  just shows the error as a line of text. Not very human friendly.
- There's a `loading` flag threaded through but the UI doesn't yet use these values
- I would want validation to come from a openapi spec
- Caching for repeated requests

## How I used AI

I used Claude code CLI to generate code throughout the project. Most of the code was generated by AI but none is
committed without my reviewing it. I use AI to generate code because it's a lot quicker than writing it by hand,
particularly when the solution is well-defined and there's a lot of boilerplate. My main focus when tackling a new
feature is to extract the requirements into a succint prompt that can then be iterated upon - taking a much more
requirement-focused approach to solving problems. While Claude works I prefer to use my time to focus on
validation/testing, code review and identifying edge cases.
